## 二、提交前检查

1. 打开 `03_源代码文档.pdf`，确认页脚是“第 1 页 共 60 页”到“第 60 页 共 60 页”，页眉是软件全称 + V1.0 + 源程序。
2. 打开 `02_软件说明书.pdf`，确认封面名称、版本、著作权人、编制日期正确，目录 3 页，正文从第 5 页开始，最后一页是附录 D。
3. 搜索两份 PDF，确认没有 `23ZBZ`、`sk-`、`LTAI`、`AKID` 等密钥片段；源码里的腾讯地图 key 已改为只读环境变量。
4. 确认说明书里的截图没有真实用户隐私；当前截图使用种子账号 demo/alice，图片来自种子数据的 Unsplash 链接。
5. 确认申请表、说明书封面、源码页眉三处的软件全称和版本号一致。
6. 确认开发完成日期不晚于首次发表日期；当前为 2026-11-01 / 2026-11-01。
7. 如果按“未发表”申请，申请表选“未发表”，并把 `meta.json` 的 `dates.published` 改为 `false`，重新生成说明书封面（首次发表日期不会出现在封面上，但保持信息一致）。
8. 身份证扫描件清晰、四角完整、无反光；文件大小按官网要求压缩。
9. 在线表单里的“主要功能”如果字数超限，保留说明书 1.4 节的前 6 项，删掉小程序端和运维能力两项。
10. 提交前把 PDF 文件名改成官网要求的格式；如果官网不允许中文文件名，用 `source_code_V1.0.pdf` 和 `manual_V1.0.pdf`，内容不变。

## 三、在线提交步骤

1. 打开中国版权保护中心官网，注册账号并完成实名认证。
2. 进入“软件著作权登记”在线填报，按 `01_申请表信息.md` 填软件信息、著作权人信息、开发信息。
3. 上传 `03_源代码文档.pdf` 和 `02_软件说明书.pdf`；按页面提示上传身份证明。
4. 选择普通办理或加急办理；费用和时限以官网当期公示为准。
5. 提交后保存受理号，按官网通知补正或缴费。
6. 审核通过后下载电子证书；纸质证书按官网说明领取或邮寄。

## 四、常见驳回原因与处理

| 驳回原因 | 处理 |
|---|---|
| 源代码页数不足或不是 60 页 | 本项目固定 60 页；如果改过 `meta.json` 的 `source_pages`，重新生成并核对页脚 |
| 每页行数不足 50 行 | 生成脚本按 50 行/页切分；如果换行导致行数变化，重新运行 `build_source.sh` |
| 源码页眉与申请表名称不一致 | 改 `meta.json` 的 `software.full_name`，运行 `sync_meta.py`，再重建两份 PDF |
| 代码与说明书功能不一致 | 说明书按当前代码写；如果删了功能，先改说明书再提交，不要只改代码 |
| 源码含第三方版权头 | 样本已排除 `typings/`、`node_modules`、`dist`、`target`；如果新增第三方文件，加入 `source_manifest.json` 的排除规则 |
| 源码含密钥 | 已移除硬编码腾讯地图 key；提交前再搜一遍 `23ZBZ`、`sk-`、`LTAI`、`AKID` |
| 说明书页数不在 30–60 页 | 当前 47 页；改内容后运行 `build_manual.sh`，看输出的 `pages=` 是否在范围 |
| 截图模糊或含隐私 | 重新用 browser-use 截 1440×900 或 390×844，使用种子账号，不要用生产真实用户数据 |
| 软件名称含受限词 | “南粤”“入境游”“AI”当前可正常申请；如被要求修改，改 `meta.json` 后重建 |
| 申请表与说明书日期矛盾 | 申请表用 `dev_completed`/`first_published`；说明书封面用 `doc_date`；三者在 `meta.json` 中分开维护 |

## 五、修改信息后如何重新生成

所有可变信息集中在 `docs/copyright/meta.json`：

```json
{
  "software": { "full_name": "...", "short_name": "...", "version": "V1.0" },
  "owner": { "name": "...", "id_number": "...", "address": "..." },
  "dates": { "dev_completed": "2026-11-01", "first_published": "2026-11-01", "doc_date": "2026-11-10" }
}
```

改完后执行：

```bash
cd D:/code/Travel_Guangdong
bash docs/copyright/scripts/build_manual.sh
bash docs/copyright/scripts/build_source.sh
```

- `build_manual.sh` 会先运行 `sync_meta.py`，把 `meta.json` 的名称/著作权人/版本/日期写进说明书 YAML，再生成 HTML、PDF、DOCX。
- `build_source.sh` 会重建 60 页源码 PDF/DOCX，并运行 `validate_source.py` 检查页数、页眉、首尾文件和密钥。
- 如果只改说明书文字，不改 `meta.json`，直接运行 `build_manual.sh` 即可。
- 如果只改源码，不改文件顺序，直接运行 `build_source.sh`；如果新增/删除文件，改 `scripts/source_manifest.json` 后重跑。

## 六、安全与合规提醒

- `deploy/app.env`、`web/.env.local`、`.env` 不要提交到仓库，也不要放进软著材料。
- 云函数 `aiService` 的腾讯地图 key 已改为只读 `process.env.TENCENT_MAP_API_KEY`；如果该 key 曾经出现在聊天记录、截图或旧提交里，去腾讯位置服务控制台轮换。
- 高德 JS key 可以出现在前端 bundle，但要配置域名白名单；Web 服务 key 只放后端 `AMAP_WEB_KEY`。
- 截图里的 Unsplash 图片仅用于界面演示；如果审查机构要求替换为自有素材，换 `sql/seed.sql` 的图片 URL 后重新截图。
- 本指南不代替法律意见；如果以学校/公司名义申请，先确认代码是否为职务作品、是否需要单位授权。
